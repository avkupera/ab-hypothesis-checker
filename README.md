# AB-шаблоны: комплект файлов команды для A/B-теста

Как пользоваться: скопируйте файлы в репозиторий проекта (или в общую папку команды), удалите строки-примеры и заполните своими данными.

## Состав комплекта

| Файл | Что это | Где живёт |
|---|---|---|
| `Шаблон_файла_команды.xlsx` | Пустой файл команды: «Как заполнять», «Спецификация», «Журнал», «Данные», «Дашборд», скрытые «Итоги» и «Расчёт_графиков» | Общая папка/диск команды |
| `Пример_файла_команды_с_графиками.xlsx` | Тот же файл, полностью заполненный учебным примером (кнопка 17 → 22 px): видно, как выглядят формулы, итоги и все графики | Для образца; свои данные не вносить |
| `Шаблон_отчёта_AB-теста.md` | Отчёт об эксперименте по 7 полям | Репозиторий: `reports/YYYY-MM-DD_короткое-название.md` |
| `Шаблон_user_testing.md` | Юзабилити-тест: сценарий, задания, анкета SUS, форма результатов | Репозиторий: `reports/YYYY-MM-DD_usability.md` |
| `glossary.md` | Глоссарий терминов проекта | Корень репозитория |

## Что считается само (не вписывайте руками)

- **Спецификация:** p₂ = p₁ × (1 + MDE); объём выборки n на вариант (формула z-теста); срок в днях и неделях (целые недели, минимум 7); дата финиша; проверка реалистичности срока. Вводятся только база p₁, MDE, α, мощность, визиты в день и дата старта.
- **Дашборд:** собранные визиты A и B, % от планового n, доля B в трафике, проверка баланса 50/50 и четыре диаграммы: визиты по дням, накопленный трафик против плана, баланс A/B, баланс каналов.
- **Итоги (скрытый лист):** конверсии, прирост в п. п. и в %, z, p-value, 95% ДИ, подсказка по решению, фактический MDE и три диаграммы: конверсии с ДИ, прирост с ДИ, накопленная конверсия по дням.

## Защита от подглядывания

- На листе «Данные» нет конверсий и итогов — только визиты и события по дням.
- На «Дашборде» нет результатных метрик.
- «Итоги» скрыты; пока в ячейке B3 стоит «НЕТ», результаты закрыты. Чтобы открыть: правый клик по ярлыкам листов → «Показать», затем «ДА» в B3 — только после даты финиша и записи в «Журнале».

## Как связаны файлы

1. **До запуска:** заполнить «Спецификацию», в «Журнал» внести настройку цели и запуск.
2. **Во время теста:** ежедневно вносить визиты и события в «Данные» (две строки в день: A и B), события — в «Журнал»; раз в день смотреть «Дашборд».
3. **После теста:** открыть «Итоги», записать решение и обоснование, перенести числа в отчёт по шаблону.

## Чек-лист готовности к запуску

- [ ] В Метрике создана цель (например, lead_click) и проверена в реальном времени
- [ ] Собраны UTM-метки для вариантов и каналов; ссылка с меткой открывается, визит виден в отчёте
- [ ] В файле команды заполнена вся «Спецификация»; «Проверка срока» показывает «Срок реалистичен»
- [ ] В «Журнале» записаны настройка цели и запуск, приложены доказательства
- [ ] Скриншот работающей цели отправлен в чат команды

## Правила, которые нельзя нарушать

- За один тест меняется один элемент; основная метрика одна, знаменатель зафиксирован письменно.
- MDE — одно число; расчёт выборки до старта; срок — целые недели (минимум 7).
- Решение — один раз, в конце срока, без подглядывания.
- Свои визиты размечайте `utm_source=self` и исключайте из данных; каждый случай — запись в «Журнале».
- «Данных не хватило» — нормальный профессиональный вывод: «незначимо» не значит «эффекта нет».
